## 问题 4 [IMPLEMENTATION]

请分析你修改后的 `iput` 函数实现：



请解释判断条件 `ip->ref == 1 && ip->nlink == 0` 的深层含义：

1. 为什么必须同时满足 `ref == 1`？如果 `ref > 1` 但 `nlink == 0`，此时能否释放文件？
2. `ref` 和 `nlink` 分别代表什么？它们的生命周期有何不同？
3. 如果在这里错误地释放了正在被其他进程使用的 inode（即 `ref > 1`），会导致什么内存安全问题？

**参考代码**:

```
void iput(struct inode *ip) {
    acquire(&icache.lock);
    
    // 实验提示要求取消注释并修改的这段判断
    if(ip->ref == 1 && ip->valid && ip->nlink == 0) {
        release(&icache.lock);
        
        ilock(ip);
        itrunc(ip);       // 释放所有数据块
        ip->type = 0;     // 标记inode为空闲
        iupdate(ip);      // 写回磁盘
        ip->valid = 0;
        iunlock(ip);
        
        acquire(&icache.lock);
    }
    
    ip->ref--;            // 减少引用计数
    release(&icache.lock);
}
```

**出题理由**: 该问题深入考察 `iput` 的核心逻辑，这是硬链接实现的关键函数。`ref` 是内存中的临时引用（open file descriptors），`nlink` 是持久化的目录项引用。只有当两者都为 0 时才能真正删除文件。这体现了文件系统中"最后一个关闭者清理"（last one to close cleans up）的设计模式。
