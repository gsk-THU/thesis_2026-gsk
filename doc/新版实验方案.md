# AI 口试系统效果实验方案

## 1. 实验目标

本实验用于验证系统在“文字考试功能”下对不同理解水平学生答案的区分能力、评分稳定性、评分一致性和重评机制有效性。实验不依赖真实学生参与，而是使用大语言模型生成不同等级的模拟学生答案，再将这些答案输入系统进行自动出题与评分。

实验核心问题如下：

1. 系统能否对“优秀、良好、及格、不及格”四类模拟学生答案给出单调递减的评分。
2. 系统能否稳定地区分相邻等级，尤其是“良好”和“及格”的边界。
3. 多模型委员会评分是否比单模型评分更稳定。
4. 离群值检测与自动重评机制是否能识别异常评分，并降低异常评分对最终结果的影响。
5. 系统生成的反馈是否能指出答案中的真实知识缺陷。

## 2. 实验对象与范围

实验对象为项目中的文字考试流程：

- 启动考试接口：`POST /api/evaluation/start`
- 提交答案并评分接口：`POST /api/evaluation/{evaluation_id}/complete`
- 状态查询接口：`GET /api/evaluation/{evaluation_id}`

本实验不测试实时语音交互、ASR、TTS、前端录音体验等语音链路，只评估“出题 + 文字回答评分 + 多模型委员会裁定 + 重评机制”的效果。

## 3. 实验总体设计

实验采用“固定原始题目 + 模拟不同水平学生答案 + 系统自动生成深度测试问题 + 模拟学生回答深度测试问题 + 系统评分”的流程。

完整流程如下：

1. 选取若干个操作系统实验主题作为原始题目。
2. 为每个原始题目编写或生成一份专家参考答案。
3. 使用 LLM 生成四个等级的模拟学生初始答案：优秀、良好、及格、不及格。
4. 对每份模拟初始答案调用 `/api/evaluation/start`，让系统生成深度测试问题。
5. 针对系统生成的每个深度测试问题，再使用 LLM 按同一等级生成模拟学生回答。
6. 调用 `/api/evaluation/{evaluation_id}/complete` 提交这些回答，获得系统评分报告。
7. 对评分结果进行统计分析，评估系统区分度、单调性、一致性和重评效果。

该设计保留系统真实使用方式：系统会根据学生初始答案动态生成追问，因此不同等级学生面对的问题可能不同。这更接近真实考试场景，也能测试出题模块是否会根据答案水平调整问题深度。

为增强可比性，可增加一个“固定题组补充实验”：先用专家答案生成一套深度测试题，然后把同一套题人工复制为测试题组，让四类模拟学生回答同一批问题。该补充实验用于排除“不同学生面对不同题目”带来的混杂影响。

## 4. 实验数据集构建

### 4.1 原始题目选择

建议选择 8 至 12 个 OS 实验主题，覆盖不同知识模块。最小可运行实验可先选择 6 个主题。

推荐题目如下：

| 编号 | 模块 | 原始题目 |
|---|---|---|
| T1 | 进程管理 | 请说明你在 rCore 中实现任务分时轮转调度的核心代码逻辑，并解释任务切换时上下文保存与恢复的过程。 |
| T2 | 系统调用 | 请说明你如何在内核中添加一个新的系统调用，包括用户态接口、系统调用号分发和内核处理函数。 |
| T3 | 内存管理 | 请解释多级页表映射的建立过程，并说明页表项有效位、物理页号和访问权限位的作用。 |
| T4 | 中断与异常 | 请说明 trap 处理流程中用户态到内核态切换的关键步骤，以及 trap 上下文为何需要保存。 |
| T5 | 文件系统 | 请解释 inode、文件描述符和文件读写接口之间的关系，并说明一次 read 系统调用的大致路径。 |
| T6 | 同步互斥 | 请说明信号量或互斥锁在内核并发控制中的作用，并分析死锁可能出现的条件。 |
| T7 | 页面置换 | 请比较 FIFO、LRU 和 CLOCK 页面置换算法，并说明你会如何在教学内核中实现 CLOCK。 |
| T8 | 地址空间 | 请解释地址空间切换时页表根寄存器变化的意义，以及为什么不同进程需要隔离的虚拟地址空间。 |

每个题目应附带一份专家参考答案。参考答案可由教师编写，也可由 LLM 生成后人工校对。

### 4.2 模拟学生等级定义

本实验定义四个模拟学生等级：

| 等级 | 标签 | 预期水平 | 预期系统分数区间 |
|---|---|---|---|
| 优秀 | A | 概念准确，能联系代码和 OS 原理，能说明边界情况与设计取舍 | 8.5-10 |
| 良好 | B | 核心概念基本正确，能解释主要流程，但细节或边界情况不完整 | 7-8.5 |
| 及格 | C | 只掌握表层概念，回答较泛化，能说出部分关键词但缺少机制解释 | 5-7 |
| 不及格 | D | 概念混淆、答非所问或严重依赖套话，无法解释关键机制 | 0-5 |

每个原始题目、每个等级生成 5 份不同模拟学生答案。因此若使用 8 个题目，总初始答案数量为：

`8 题 × 4 等级 × 5 份 = 160 份`

若先做小规模试运行，可使用：

`3 题 × 4 等级 × 3 份 = 36 份`

## 5. 模拟答案生成细则

### 5.1 初始答案生成 Prompt

对每个原始题目，使用如下 prompt 生成模拟学生初始答案。

```text
你正在模拟一名操作系统课程学生。请根据指定水平，回答下面的实验口试题。

【原始题目】
{original_question}

【学生水平】
{level_description}

【生成要求】
1. 只输出学生答案本身，不要输出评分、解释或分析。
2. 答案必须像真实学生口头或书面回答，不要过于完美。
3. 答案长度控制在 150-350 字。
4. 如果是优秀水平，需要体现机制理解、代码关联、边界情况或设计取舍。
5. 如果是良好水平，需要核心正确但保留少量遗漏。
6. 如果是及格水平，需要有一些关键词，但解释浅、细节不足。
7. 如果是不及格水平，需要出现明显概念混淆、空泛套话或错误理解。
8. 不要直接说明“我是优秀/及格学生”。

请生成答案：
```

其中 `{level_description}` 使用以下四种描述：

优秀：

```text
优秀。该学生真正完成过实验，能较准确解释 OS 机制和代码实现，能说明关键边界情况。
```

良好：

```text
良好。该学生基本完成实验，理解主要流程，但对少数底层细节、异常路径或设计取舍解释不完整。
```

及格：

```text
及格。该学生看过实验材料，也能说出一些关键词，但回答偏记忆化，缺少对代码和底层机制的深入解释。
```

不及格：

```text
不及格。该学生没有真正理解实验，只能给出空泛描述，可能混淆概念，无法解释关键机制。
```

### 5.2 深度测试问题回答生成 Prompt

系统通过 `/api/evaluation/start` 生成深度测试问题后，对每个问题使用如下 prompt 生成模拟学生回答。

```text
你正在模拟一名操作系统课程学生参加 AI 文字口试。请根据指定水平回答考官问题。

【原始实验题目】
{original_question}

【学生初始答案】
{initial_answer}

【考官追问】
{exam_question}

【学生水平】
{level_description}

【回答要求】
1. 只输出学生对该追问的回答，不要输出分析、评分或标题。
2. 答案应与学生水平一致，不能突然变得比初始答案强很多。
3. 优秀水平应具体解释机制，并尽量联系代码或实现细节。
4. 良好水平应回答主要点，但可以遗漏边界情况。
5. 及格水平应有部分正确关键词，但解释浅，可能缺少因果关系。
6. 不及格水平可以答非所问、概念混淆或明显空泛。
7. 答案长度控制在 80-250 字。

请生成回答：
```

### 5.3 生成质量控制

为避免模拟答案质量失控，需要进行以下检查：

1. 每份答案必须标注真实等级标签，但标签只保存在实验数据表中，不输入系统评分接口。
2. 每个等级抽样 10% 答案进行人工检查，确认等级符合预期。
3. 若“不及格”答案被生成得过于正确，应重新生成。
4. 若“优秀”答案只是堆砌术语但没有机制解释，应重新生成。
5. 同一题目同一等级的 5 份答案应具有差异，避免完全模板化。

```bash
cd /path/to/thesis_2026-gsk/api
python server.py
```

服务启动后访问：

```text
http://localhost:8000/
```

确认返回服务信息。

### 6.2 单条样本执行流程

对于每个样本，先调用启动接口。

请求：

```http

Content-Type: application/json
```

请求体：

```json
{
  "original_question": "请解释多级页表映射的建立过程，并说明页表项有效位、物理页号和访问权限位的作用。",

  "subject": "os_experiment"

```

返回中记录：

- `evaluation_id`
- `exam_questions`
- `question_count`

然后针对返回的每个 `exam_question` 生成模拟回答，并调用评分接口。

请求：

```http
POST http://localhost:8000/api/evaluation/{evaluation_id}/complete
Content-Type: application/json
```

请求体示例：

```json
{
  "exam_answers": {
    "q1": "模拟学生对 q1 的回答",
    "q2": "模拟学生对 q2 的回答",
    "q3": "模拟学生对 q3 的回答"
  }
}
```

返回中记录：

- `overall_assessment.understanding_level`
- `overall_assessment.confidence`
- 每题 `final_score`
- 每题 `grade`
- 每题 `confidence`
- 每题 `teacher_scores`

- 每题 `reevaluation`

## 7. 评价指标

### 7.1 评分单调性

对每个题目计算四个等级的平均系统得分：

```text
mean(A), mean(B), mean(C), mean(D)
```

理想结果：

```text
mean(A) > mean(B) > mean(C) > mean(D)
```

单调性指标：

```text
monotonic_topics = 满足严格单调的题目数 / 总题目数
```

验收标准：

```text
monotonic_topics >= 0.75
```

即至少 75% 的题目满足四等级均值单调递减。

### 7.2 等级区分度

计算相邻等级均值差：

```text
ΔAB = mean(A) - mean(B)
ΔBC = mean(B) - mean(C)
ΔCD = mean(C) - mean(D)
```

验收标准：

```text
整体平均 ΔAB、ΔBC、ΔCD 均 >= 0.8 分
```

如果某一组小于 0.8，说明系统对相邻等级区分不明显，需要分析题目或评分提示。

### 7.3 排名相关性

将真实等级映射为数值：

```text
A=4, B=3, C=2, D=1
```

计算真实等级与系统平均分之间的 Spearman 等级相关系数。

验收标准：

```text
Spearman ρ >= 0.75
```

### 7.4 分类准确率

将系统平均分映射回等级：

| 平均分 | 系统预测等级 |
|---|---|
| 8.5-10 | A |
| 7-8.49 | B |
| 5-6.99 | C |
| 0-4.99 | D |

计算：

```text
accuracy = 预测等级等于真实等级的样本数 / 总样本数
```

同时允许相邻等级误差，计算：

```text
adjacent_accuracy = 预测等级与真实等级差距不超过 1 档的样本数 / 总样本数
```

验收标准：

```text
accuracy >= 0.60
adjacent_accuracy >= 0.90
```

### 7.5 多模型一致性

使用每题返回的 `consensus_stats.score_distribution.std_dev` 和 `agreement_level`。

统计：

```text
高一致性比例 = agreement_level 为“高”的题目数 / 总评分题目数
低一致性比例 = agreement_level 为“低”的题目数 / 总评分题目数
```

验收标准：

```text
高一致性比例 >= 0.50
低一致性比例 <= 0.20
```

### 7.6 重评机制有效性

记录每题 `reevaluation.trigger_report.triggered` 和 `reevaluation.results`。

统计：

1. 重评触发率：

```text
trigger_rate = 触发重评的评分题目数 / 总评分题目数
```

2. 重评修正幅度：

```text
mean_abs_delta = mean(abs(score_delta))
```

3. 重评后主席是否降低低置信度：

比较触发重评样本与未触发样本的最终 `confidence` 分布。

预期结果：

- 重评触发率不应过高，否则说明阈值太敏感。
- 建议触发率范围为 5%-25%。
- 如果触发重评，`score_delta` 应主要集中在 0-2 分内。
- 低一致性样本应更容易触发重评。

### 7.7 反馈质量人工评估

随机抽取 40 份评分报告，由人工评审判断系统反馈是否合理。

人工评审维度：

| 维度 | 评分 |
|---|---|
| 是否指出真实知识漏洞 | 0/1/2 |
| 是否给出具体改进建议 | 0/1/2 |
| 是否存在明显误判或幻觉 | 0/1/2，2 表示无明显误判 |
| 评语是否与分数匹配 | 0/1/2 |

每份报告满分 8 分。

验收标准：

```text
平均反馈质量分 >= 6
明显误判率 <= 15%
```

## 8. 统计分析方法

### 8.1 描述性统计

按等级统计：

- 样本数
- 平均分
- 标准差
- 中位数
- 最小值
- 最大值
- 95% 置信区间

推荐表格：

| 等级 | N | 平均分 | 标准差 | 中位数 | 最小值 | 最大值 |
|---|---:|---:|---:|---:|---:|---:|
| A | | | | | | |
| B | | | | | | |
| C | | | | | | |
| D | | | | | | |

### 8.2 显著性检验

如果分数近似正态，可使用单因素 ANOVA 检验四个等级均值差异。

如果分数不满足正态分布，使用 Kruskal-Wallis 检验。

相邻等级可使用 Mann-Whitney U 检验或 t 检验，并报告 p 值。

建议报告：

```text
A vs B
B vs C
C vs D
```

### 8.3 效应量

仅有 p 值不够，应报告 Cohen's d 或 Cliff's delta。

验收标准建议：

```text
相邻等级 Cohen's d >= 0.5
非相邻等级 Cohen's d >= 0.8
```

## 9. 对照实验设计

### 9.1 单模型 vs 多模型委员会

目的：验证委员会评分是否比单模型更稳定。

方法：

1. 从 `teacher_scores` 中取某一个固定模型的分数作为单模型分数。
2. 将 `final_score` 作为委员会分数。
3. 分别计算单调性、等级区分度、Spearman 相关系数和标准差。

比较表：

| 方法 | 单调性 | Spearman ρ | Accuracy | Adjacent Accuracy | 平均标准差 |
|---|---:|---:|---:|---:|---:|
| 单模型 | | | | | |
| 多模型委员会 | | | | | |

预期结果：

```text
多模型委员会 Spearman ρ 更高，等级边界更稳定，极端误判更少。
```

### 9.2 有重评 vs 无重评

目的：验证自动重评机制是否降低异常评分影响。

方法：

1. 对触发重评的样本，记录主席最终分数。
2. 使用第一阶段教师平均分作为“无重评近似结果”。
3. 比较两者与真实等级的相关性和分类误差。

注意：当前系统没有直接提供关闭重评的开关。如果需要严格对照，可临时将 `detect_reevaluation_triggers` 返回 `triggered=False`，跑一轮无重评版本。论文实验阶段可以先使用“第一阶段平均分”作为近似对照。

## 10. 实验规模建议

### 10.1 小规模试运行

用于检查流程是否打通：

```text
3 个题目 × 4 个等级 × 3 份答案 = 36 个样本
```

每个样本生成 3-5 个深度测试问题，总评分题目约 108-180 个。

### 10.2 正式实验

用于论文报告：

```text
8 个题目 × 4 个等级 × 5 份答案 = 160 个样本
```

每个样本生成 5 个深度测试问题，总评分题目约 800 个。

若 API 成本或时间受限，可采用：

```text
6 个题目 × 4 个等级 × 4 份答案 = 96 个样本
```

## 12. 结果判定标准

系统达到以下条件，可认为实验结果支持系统有效性：

1. 四等级平均分整体呈单调递减，单调题目比例不低于 75%。
2. Spearman 等级相关系数不低于 0.75。
3. 严格分类准确率不低于 60%，相邻等级准确率不低于 90%。
4. 相邻等级平均分差不低于 0.8 分。
5. 高一致性评分题目比例不低于 50%，低一致性比例不高于 20%。
6. 重评触发率处于 5%-25% 合理范围，且主要集中在模型分歧较大的样本上。
7. 人工抽检反馈质量平均分不低于 6/8，明显误判率不高于 15%。

若未达到上述标准，应进一步分析：

- 模拟答案等级是否生成准确。
- 原始题目是否过于宽泛。
- 系统生成的深度测试问题是否有足够区分度。
- 评分 prompt 是否过度宽松或过度严格。
- 重评阈值是否过敏或过钝。

## 14. 风险与控制

### 14.1 LLM 生成答案偏差

风险：LLM 生成的“不及格答案”可能仍然较正确，导致等级不明显。

控制：抽样人工检查，必要时加强 prompt 中的错误要求。

### 14.2 系统出题不固定

风险：不同等级答案触发不同深度测试问题，导致评分差异部分来自问题难度。

控制：保留真实流程实验，同时增加固定题组补充实验。

### 14.3 评分模型与答案生成模型同源

风险：若答案生成模型与评分模型相同，可能出现模型偏好。

控制：尽量使用不同模型生成模拟答案，例如用一个模型生成答案，用系统中的 Kimi 委员会评分；或者至少记录生成模型并在论文中说明限制。

### 14.4 API 随机性

风险：同一答案多次评分可能有波动。

控制：对 10% 样本重复评分两次，计算重复评分差异。若平均差异超过 0.8 分，需要降低评分 temperature 或强化输出约束。

## 15. 最小可执行实验清单

如果时间有限，按以下最小清单执行：

1. 选择 T1、T3、T4 三个题目。
2. 每题每等级生成 3 份初始答案，共 36 份。
3. 每份答案调用文字考试接口生成 3 个深度测试问题。
4. 对每个深度测试问题生成同等级模拟回答。
5. 调用评分接口，保存完整 JSON 返回。
6. 统计四等级平均分、Spearman 相关、分类准确率、重评触发率。
7. 抽查 12 份评分报告做人工反馈质量评价。

该最小实验可作为系统可行性验证；正式论文实验建议扩展到至少 96 份样本。
